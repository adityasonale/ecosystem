Veronica

A central tool server. It holds the OAuth tokens for third-party services and exposes them in two ways: as MCP tools over SSE, which is how Karen and other agents use them, and as a small REST API for programs that aren't agents. Every request needs an API key.

Endpoints

EndpointForNotes
/mcp/sseMCP clients (Karen)The tool list and tool calls over SSE. Mounted under /mcp
POST /send-emailNotifications to the owner (Karen's email notification channel){to, subject, body, cc?} → {status, message, id}. Sends only to the owner's addresses (VERONICA_NOTIFY_RECIPIENTS): another recipient gets 403, and an unset allowlist gets 503. A failed send gets 502

Both go through APIKeyMiddleware, so every request needs a key from secrets/clients.json.

Karen sees these as veronica__<tool>, namespaced by mcp_client/mcp_tool_adapter.py. Tools are async and call Gmail and Spotify with httpx. A failure comes back as {"error": "..."} from api_error_response, written for the LLM to act on. For example, "Rate limited during …. Wait a moment and try again." or "Authentication failed or expired during …".

Adding an integration

  1. Create veronica/integrations/<service>/ with auth.py and tools.py, plus a settings class in config.py.
  2. Register each tool with @mcp.tool() in mcp_server.py. The docstring becomes the description the LLM sees.
  3. In Karen, the tools appear automatically in the CapabilityCatalog. Give each one a line in Karen's config.yaml: tool_policy with its group and risk (anything that sends, pays, posts or deletes for good is high, which makes Karen ask first). Without a line, a tool is high risk and no agent binds it. Add an action agent only if the tools need their own planning route.

Things to know: Gmail refresh tokens expire after 7 days while the Google app is in testing mode, which means signing in again regularly.

Two routes for email, two levels of protection. The MCP send_email tool can email anyone, but Karen asks you before every send. POST /send-email has no approval step, so it can only email your own addresses. A leaked key could only ever email you through that route.
