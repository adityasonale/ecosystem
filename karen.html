Karen: packages & components

Karen is a LangGraph application wrapped in a dependency container. Interfaces pass text in, the graph decides what to do, and every heavy resource is created once at startup and shared.

Dependencies point downward only. Interfaces don't know about LangGraph, and agents don't know which interface is calling.

Startup sequence

  1. main.py loads settings.CONFIG: config.yaml with config.local.yaml deep-merged on top.
  2. start_ecosystem() (core/ecosystem.py) starts each service in config.local.yaml: ecosystem in order (Redis, Qdrant, the Celery worker, llm-server, the gateway, Veronica) and waits for its port; one already running is reused. A service with no port, like the worker, is checked for not exiting on startup. Services Karen started stop when it exits. No ecosystem entry (Docker, the VM) starts nothing.
  3. AppContainer(config, mode) creates the database tables and reschedules pending reminders, then creates the ThreadWorker, one QdrantClient, one embedding model, Memory (given the ThreadWorker for background writes), and the document sync plus the HybridRetriever (with the reranker). It creates a Speaker only in online/voice mode. Last, it creates an empty MCPToolRegistry and the ToolRegistry (container.tools) over it plus the local tools and tool_policy.
  4. container.init_mcp() connects to every mcp_servers entry (Veronica), lists its tools, and wraps each one as a LangChain tool named server__tool, with typed arguments. It fills the existing MCPToolRegistry in place, so the ToolRegistry sees them.
  5. container.build() creates VirtualAssistant. That builds the CapabilityCatalog, the four orchestration agents, and every action agent through Agent.from_container(container), then compiles the graph.
  6. The selected interface starts its loop and calls assistant.run() for each message.

Configuration

SourceHoldsCommitted?
config.yamlShared defaults: llm block, retrieval, memory, Celery, personas, mcp_servers, tool_policy (group and risk for each MCP tool), terminal (the terminal agent's roots, timeout and output cap)Yes
config.local.yamlPer-machine overrides (model paths), deep-merged over the defaultsNo (gitignored; see config.local.example.yaml)
.envSecrets: LLM_SERVER_API_KEY, VERONICA_API_KEY, TAVILY_API_KEY, DiscordNo
EnvironmentLLM_SERVER_URL overrides llm.base_url (e.g. in Docker)

One rule per concern. Each of these has exactly one place: models in llm/client.py, agents in registry.py, capabilities in CapabilityCatalog, tools and their labels in ToolRegistry, config in settings.CONFIG, heavy resources in AppContainer. A second place is the first sign of drift.
