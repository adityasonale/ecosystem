The ecosystem

Three services, each with one job. Karen decides what to do, llm-server does the language-model work, and Veronica touches the outside world. They connect only over HTTP, so any one of them can be swapped out, moved to another machine, or reused by a new client.

Karen

The personal assistant: a LangGraph orchestrator that routes, plans, runs agents, and remembers.

client · :8000 in API mode

llm-server

The gateway for local LLMs. It exposes an OpenAI-compatible API and serves local models only.

gateway · :8100

Veronica

An MCP tool server that holds the OAuth tokens and calls Gmail and Spotify.

tool server · :8200

Infrastructure

llama-server (Bonsai 27B), Redis + Celery, Qdrant (local files), SQLite.

:8089 · :6380

Who owns what

ConcernOwnerWhy there
Deciding what to do with a messageKarenOrchestration is the assistant's job. Routing, planning and memory all stay in one place.
Which model runs, and howllm-serverKaren only names a model (llamacpp/bonsai-27b). llm-server maps the name to a path in models.yaml, picks a backend plugin, and starts it. Swapping models is a models.yaml change.
Model weights, the GPU, inferencellama-serverllama.cpp already does streaming and tool calling well. llm-server forwards to it rather than reimplementing it.
Third-party credentials (Google, Spotify)VeronicaOAuth tokens live in one service. Any MCP client (Karen, Claude, a future app) reuses the same tools.
What Karen can doKaren CapabilityCatalogBuilt live from the registered agents and whichever MCP tools are connected, never from a hand-kept list.
Long-running and timed workCelery + RedisA reminder must fire even if the process that created it is busy. Startup reschedules any pending reminders from SQLite.
