llm-server

A personal LLM gateway built with FastAPI. Clients use the standard OpenAI chat-completions API and ask for a model by name. llm-server looks the name up in models.yaml, detects the model's format from its path, starts a backend plugin that suits the format and the machine, and forwards the request. It authenticates, routes, sets limits, records traces, and maps errors into the OpenAI error shape. It serves local models only.

Model loading: backend plugins

A model is a name and a path in the gitignored, per-machine models.yaml, with optional args, sampling defaults, a pinned backend, a port and a startup_timeout. The file is read again whenever it changes, so adding a model needs no restart. The first request for a model starts its backend. A request for a different model waits for in-flight requests to finish, then stops the old backend and starts the new one. The size check runs before the old model stops, so a model too big for the machine gets a 400 and the current one stays loaded.

A plugin is a backends.base.Backend subclass. It declares its formats and priority, says whether it can run on the detected hardware, and implements start, stop, chat_completion and open_stream. Extra plugins load from plugins: in models.yaml as module:Class.

Backpressure

The local provider has one GPU, so it runs one generation at a time behind an asyncio.Lock.

  • When the queue is already at MAX_INFLIGHT_REQUESTS, the request is refused at once with 503 + Retry-After.
  • A request that waits longer than QUEUE_TIMEOUT_SECONDS also gets a 503.
  • Karen's ChatOpenAI(max_retries=2) retries 503 responses with backoff. That's how the client and server sides of this fit together.

The model behind it today

Ternary-Bonsai-2-27B-PQ2_0.gguf on the PrismML llama.cpp fork (PQ2_0 kernels), Metal, -ngl 99, 8K context on the 16 GB M4 Air. It's registered as bonsai-27b in models.yaml, and llm-server starts it on port 8089 with the model card's thinking-mode sampling as defaults. It generates about 10.7 tok/s and processes prompts at 25–45 tok/s. Karen turns thinking off (reasoning_effort: none) for routing, planning, conversation and memory extraction.
