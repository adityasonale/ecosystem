Gateway

The front door for every model call. It's a pinned LiteLLM Proxy with its own Postgres, run by Docker Compose from ~/projects/gateway. Each client gets its own virtual key, which can carry rate limits, budgets and a list of allowed models, and every request is logged against that key. The gateway forwards to the model hosts behind it. Today that's llm-server only, which serves local models. Hosted models can be added here later without changing llm-server's local-only rule. The gateway has no code of its own: it is litellm_config.yaml, docker-compose.yml and .env.

llm-server accepts only the gateway's key, so the gateway is the only way to reach the models.

What it owns

ConcernHow
Who may callVirtual keys (sk-…), one per client, created with the master key through /key/generate or the admin UI at :4000/ui. Karen's key is called karen.
How muchPer-key rpm_limit and tpm_limit (429 when exceeded), budgets, and an allowed models list. Karen's key (karen) has rpm_limit: 60, about three times its busiest minute so far (18), as a guard against a runaway agent loop; Karen's client retries a 429 only twice, so a limit it hits fails the turn. There's no tpm_limit: the GPU caps throughput at roughly 44k tokens a minute anyway. Benchmarks (bench_routing.py) use their own unlimited key, bench.
UsageEvery request is logged in Postgres against its key (LiteLLM_SpendLogs), so usage can be told apart per client. llm-server sees a single caller.
Which host serves a modelmodel_list in litellm_config.yaml. Today it's one wildcard entry: every model name goes to llm-server unchanged, so llm-server's models.yaml stays the only list of local models.
Retriesnum_retries: 2, so llm-server's 503 + Retry-After during a model swap is retried before it reaches the client. request_timeout: 300 matches llm-server.

The route

model_list:
  - model_name: "*"
    litellm_params:
      model: "openai/*"                        # OpenAI-compatible upstream, name passed through
      api_base: os.environ/LLM_SERVER_BASE_URL # default http://host.docker.internal:8100/v1
      api_key: os.environ/LLM_SERVER_API_KEY   # the gateway's entry in llm-server's API_KEYS

Request bodies pass through untouched apart from the key: tools, streaming, and non-standard fields like chat_template_kwargs (Karen's thinking switch) reach llama-server. That was checked with a plain call, a stream, a tool call, thinking on and off, and a per-key rate limit.

Virtual keysPostgres (hashed); each client's .envClients calling the gateway. Karen keeps its key in LLM_SERVER_API_KEY (the variable name is unchanged) and the benchmark key in BENCH_API_KEY.

Compose passes the LiteLLM container only the variables it needs, never the whole .env. The image is pinned to an exact tag (ghcr.io/berriai/litellm:v1.108.6, the LTS line with the latest security backport) because the gateway sits on every model call; bump it deliberately, never to main-latest.

Running

  • docker compose up -d --wait in ~/projects/gateway. Karen's config.local.yaml: ecosystem runs that after llm-server.
  • Port 4000 opens about 30 s before LiteLLM can answer, while it runs its database migrations. A healthcheck on /health/liveliness makes --wait return only once it actually serves, so Karen's launcher doesn't move on too early.
  • llm-server runs natively on the host, because it needs the GPU. The container reaches it at host.docker.internal:8100.

Not behind it: Veronica

LiteLLM can also front MCP servers, but Veronica stays direct on :8200 for now. It already has its own per-client keys, Karen is its only client, and its REST /send-email couldn't move anyway. Moving it would likely mean a transport change in Karen's MCP client (SSE vs streamable HTTP) and prefixed tool names that would no longer match Karen's tool_policy. It becomes worth it with a second client, or once per-client tool permissions or one usage log for models and tools is wanted.

Next for the gateway: test that a 503 during a model swap is retried rather than surfaced (needs a second model), hosted models as their own model_list entries, and Veronica's tools behind it when the conditions above hold.
